===============================
 Summary of the Code Functionality
===============================

The script automates data retrieval and normalization 
from external REST/OData endpoints.


----------------
 Setup
----------------
Creates directories:
  • incoming/  → for downloaded data files
  • logs/      → for daily log files

Builds a base configuration including:
  • CAP_BASE_URL (possible REST/OData endpoints)
  • Basic Auth credentials


----------------
 Data Retrieval
----------------
• Fetches data via curl (Basic Auth, Accept: application/json)
• Tries each endpoint sequentially until one returns a successful (HTTP 2xx) response


----------------
 Data Processing
----------------
decode_items() parses the JSON response, supporting:
  • a plain array → [ {...}, {...} ]
  • a wrapped structure → { "items" | "value" | "data": [ ... ] }

map_row() converts each product record into the target schema:
  - erp_id
  - name
  - description
  - price
  - stock
  - active

Required fields:
  • erp_id
  • name
  • price
  • stock

Optional fields:
  • description
  • active (defaults to true)

Additional rules:
  • Prices are normalized via normalize_price()
  • Invalid or incomplete rows are skipped and logged


----------------
 Output
----------------
Writes the cleaned dataset to:
  → incoming/products-YYYYmmdd-HHMMSS.json

Logs all actions to:
  → logs/pull-YYYYmmdd.log

On success:
  → prints "OK" to STDOUT

On failure:
  → logs the error, writes to STDERR, and exits with code 1


----------------
 Error Handling & Failover
----------------
• Global try/catch around the entire process
• Each endpoint is tested independently; failures are logged
• If no endpoint succeeds → throws:
    "No working REST endpoint..."


----------------
 Validation & Logging
----------------
• Invalid JSON or unexpected response structure triggers an exception
• Rows missing required fields are skipped
• Every step and error is timestamped and written to the daily log file
